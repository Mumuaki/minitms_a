# Спецификация: Trans.eu Scraping Service (spec_trans_eu.md)

## 1. Введение
Модуль предназначен для автоматического получения списка грузоперевозок с платформы `platform.trans.eu` путем эмуляции действий пользователя (Browser Automation / Scraping). Поскольку официальное API списка грузов недоступно, этот модуль является единственным источником данных о предложениях.

**Целевой URL**: `https://platform.trans.eu/exchange/offers`

---

## 2. Функциональные требования

### 2.1. Аутентификация

> [!IMPORTANT]
> **ПРАВИЛО (STRICT RULE): Сначала надо войти на портал https://platform.trans.eu и авторизоваться на нем. Только после успешной авторизации на портале Trans.eu возможен и разрешен запуск скрапера.** 
> Ожидаемый результат: после успешной авторизации на platform.trans.eu будет открыта страница поиска грузов https://platform.trans.eu/exchange/offers. Эта инструкция является приоритетной, её удаление запрещено.

#### Шаг 0: Проверка состояния сессии (обязательный первый шаг)

Перед любым действием скрапер **обязан** проверить два условия:
1. **Авторизован ли пользователь** — проверяется по текущему URL и наличию элементов авторизованного состояния.
2. **На какой странице находится браузер** — чтобы понять, нужен ли редирект на страницу поиска.

Возможные состояния и действия:

| Состояние | Текущий URL содержит | Действие |
|---|---|---|
| Авторизован, на нужной странице | `platform.trans.eu/exchange/offers` | Перейти сразу к установке фильтров (п. 2.2) |
| Авторизован, только что вошёл | `platform.trans.eu/trans-info` | Нажать «Поиск грузов» в левом меню (Шаг 5) |
| Авторизован, на другой странице | `platform.trans.eu` (не `/exchange/offers`, не `/trans-info`) | Перейти на `https://platform.trans.eu/exchange/offers` |
| Не авторизован | `auth.platform.trans.eu` или `platform.trans.eu/login` | Выполнить процедуру авторизации (см. ниже) |

#### Процедура авторизации (если не авторизован)

**Шаг 1**: Открыть стартовый URL — он автоматически выполнит редирект на страницу авторизации.

```
START_URL = "https://platform.trans.eu"
page.goto(START_URL)
```

> Платформа Trans.eu при переходе на стартовый URL автоматически перенаправляет браузер на `auth.platform.trans.eu` и подставляет `login_challenge` самостоятельно. Явно формировать этот параметр не требуется.

**Шаг 2**: Дождаться появления полей ввода и заполнить учётные данные из `.env`-файла.

```python
# Дождаться поля TransID
page.wait_for_selector('[aria-label="TransID"]')
page.fill('[aria-label="TransID"]', TRANS_EU_USERNAME)  # из .env
page.fill('[aria-label="Пароль"]', TRANS_EU_PASSWORD)   # из .env
```

> Учётные данные берутся исключительно из переменных окружения `TRANS_EU_USERNAME` и `TRANS_EU_PASSWORD`.

**Шаг 3**: Нажать кнопку «Вход» (зелёная кнопка `type="submit"`).

```python
page.click('button[type="submit"]')
```

**Шаг 4**: Дождаться успешного завершения логина.

```python
page.wait_for_url("**/trans-info**", timeout=30000)
```

> После успешной авторизации платформа Trans.eu автоматически открывает страницу `https://platform.trans.eu/trans-info`.
> Если редирект не произошёл в течение 30 секунд — зафиксировать ошибку `LOGIN_FAILED` и завершить задачу с соответствующим статусом.

**Шаг 5**: Найти и нажать ссылку **«Поиск грузов»** в левом меню навигации.

После логина скрапер оказывается на странице `/trans-info`. Чтобы перейти на страницу поиска грузов, необходимо найти активную ссылку в левом боковом меню:

```python
# Дождаться появления левого меню
page.wait_for_selector('a[href*="/exchange/offers"]', timeout=15000)
# Кликнуть по пункту меню "Поиск грузов"
page.click('a[href*="/exchange/offers"]')
# Дождаться открытия страницы поиска грузов
page.wait_for_url("**/exchange/offers**", timeout=15000)
```

> Целевая страница после нажатия: `https://platform.trans.eu/exchange/offers`.
> Прямой переход через `page.goto()` на `/exchange/offers` **не рекомендуется** — платформа может выполнить повторный редирект или сбросить состояние фильтров. Навигация через меню является предпочтительной.

#### Сессия и cookies
* Поддержка сохранения сессии (cookies) для минимизации количества входов.
* Автоматическая повторная авторизация при истечении сессии (повторить процедуру с Шага 0).

### 2.2. Управление фильтрами (Search Workflow)
Скрапер должен строго следовать процедуре установки фильтров, чтобы гарантировать корректную выдачу грузов.

#### Шаг 0: Подготовка фильтров (ОБЯЗАТЕЛЬНО — до ввода любых данных)
1.  Нажать кнопку **«РАЗВЕРНУТЬ ФИЛЬТРЫ»** (или `EXPAND FILTERS`) — для раскрытия базовой панели фильтров.
2.  Нажать кнопку **«БОЛЬШЕ ФИЛЬТРОВ»** (или `MORE FILTERS`) — для раскрытия полной панели (даты, параметры груза).
3.  Нажать кнопку **«Очистить фильтры»** (или `Clear filters`) — для сброса всех ранее установленных значений.

> Все три действия выполняются ДО ввода любых значений поиска.

#### Шаг 1: Инициализация полей локации (Loading / Unloading)
Процесс идентичен для полей "Загрузка" и "Разгрузка":
1.  **Клик**: Левой кнопкой мыши по полю «Найти локализацию».
2.  **Последовательный ввод до появления модального окна**:
    *   Попытка 1: `{ISO-2 страны}, {Индекс}, {Начало названия города}` (English) — например: `IT, 00131, Ro`
    *   Попытка 2: `{ISO-2 страны}, {Индекс}` — например: `IT, 00131`
    *   Попытка 3: `{ISO-2 страны}` — например: `IT`
    *   *Если модальное окно не появилось:*
    *   Попытка 4: `{Город}` на русском языке
    *   Попытка 5: `{ISO-2 страны}, {Город}` на русском языке
3.  **Обязательное условие**: Результатом правильного ввода является появление модального окна с выпадающим списком. Из списка выбрать запись с **максимальным совпадением по символам** (наиболее полная: Страна + Индекс + Город + Регион). Кликнуть для фиксации.
4.  **Радиус поиска**: После фиксации города — установить **+ 75 km**. Поле радиуса появляется только если выбрана точка вида «Страна + Индекс + Город». Если указана только страна или страна + индекс — поле радиуса может не появиться; искать его принудительно не нужно.

> **Поле «Разгрузка»**: по умолчанию оставляется **пустым**. Заполняется только при явном указании пункта разгрузки.

#### Шаг 2: Параметры груза
1.  **Weight / Вес (т)**:
    *   Поле `From` (левое): Оставить пустым или `0`.
    *   Поле `To` (правое) — значение по умолчанию: **0,9** (ноль целых девять десятых тонны).
    *   Если значение отсутствует — ввести **0,9**. Если присутствует другое значение — заменить на **0,9**.
2.  **Длина (погрузочные метры) / LDM**:
    *   Поле `From` (левое, «С») — значение по умолчанию: **4,8** (погрузочных метра).
    *   Если значение отсутствует — ввести **4,8**. Если присутствует другое значение — заменить на **4,8**.
    *   Поле `To` (правое): Оставить пустым или без изменений.

#### Шаг 3: Настройка дат (Date Filters)
1.  **Loading Date (Дата загрузки)** — два поля:
    *   Левое поле (`From` / «С»): Установить стартовую дату загрузки. **По умолчанию — текущая дата.**
    *   Правое поле (`To` / «По»): Установить конечную дату загрузки. **По умолчанию — та же дата, что и в левом поле.**
    *   **Правило валидации**: Дата `From` не может быть позже даты `To`.
2.  **Unloading Date (Дата разгрузки)** — два поля:
    *   Левое поле (`From` / «С»): Установить начало окна разгрузки. **По умолчанию — правое поле «Дата загрузки» + 1 день.** Допускается оставить **пустым** при ручном вводе.
    *   Правое поле (`To` / «По»): Установить конец окна разгрузки. **По умолчанию — та же дата, что и в левом поле разгрузки.**
    *   **Правило валидации**: Дата `From` не может быть позже даты `To`.
    *   **Логическое правило (Time Continuity)**: Любая дата разгрузки (`From` или `To`) **не может быть раньше** любой даты загрузки. Если это условие нарушено, система должна отклонить запрос до взаимодействия с UI.
3.  **Алгоритм выбора даты (Calendar Workflow)**:
    *   Прямой ввод (typing) запрещен (поле readonly).
    *   Клик в поле ввода для вызова календаря.
    *   **Навигация по месяцам**: Считать заголовок календаря ("Месяц Год"). Использовать кнопки `<` (Prev) и `>` (Next) для перехода к целевому месяцу.
    *   **Выбор дня**: Найти элемент дня по ISO-идентификатору (e.g. `data-ctx-id="YYYY-MM-DD-wrapper"`). Кликнуть по элементу для выбора.

#### Шаг 4: Запуск поиска
1.  Нажать **зелёную кнопку «Поиск»** (или `Search`) в правом верхнем углу.
2.  Дождаться завершения загрузки результатов (обновления DOM).

### 2.3. Сбор данных (Extraction)
После загрузки результатов (DOM update) система должна извлечь данные из каждой карточки (Offer Card):

| Поле UI | Поле сущности `Cargo` | Преобразование |
|---|---|---|
| Место загрузки | `loading_place` | Извлечь Zip, City, Country |
| Место разгрузки | `unloading_place` | Извлечь Zip, City, Country |
| Дата публикации | `published_at` | Timestamp |
| Описание груза | `body_type`, `weight` | Парсинг строки (напр. "0.15 т, стандарт, штора") |
| Цена | `price` | Извлечь число, валюту привести к EUR |
| Расстояние (Trans) | `distance_trans_eu` | Извлечь число "km" |
| Компания | `company_name` | Название заказчика |
| Рейтинг | `company_rating` | Числовой рейтинг и кол-во отзывов |
| Trans ID | `external_id` | Уникальный ID предложения из атрибутов HTML |

### 2.4. Режимы работы
* **Интервальный**: Запуск каждые N минут (конфигурируется, min 5 мин).
* **По требованию**: Принудительное обновление по кнопке из UI.

## 3. Технические требования и ограничения

### 3.1. Нормализация данных
* **Валюта**: Все цены конвертировать в EUR. Если цена не указана, помечать как `null` или `0`.
* **Геокодирование**:
    * Полученные строковые адреса (`DE 80997 Мюнхен`) должны быть отправлены в Nominatim API (OpenStreetMap) для получения координат (`lat`, `lon`).
    * Это необходимо для корректного расчета маршрутов и отображения на карте MiniTMS.

### 3.2. Обработка ошибок
* **Изменение верстки**: При изменении CSS-селекторов на Trans.eu система должна логировать критическую ошибку и уведомлять администратора.
* **Капча/Блокировка**: Реализовать эмуляцию задержек (human-like behavior) между кликами (random 500ms - 1500ms).

### 3.3. Производительность
* Время полного цикла (Логин -> Фильтр -> Парсинг 50 грузов) не должно превышать 30-45 секунд.
