# STEP GATE — Обязательная проверка перед каждым шагом

> [!IMPORTANT]
> Агент обязан открыть этот файл через `view_file` как **первое действие** каждого шага.
> Без прохождения чеклиста шаг не может быть начат.

---

## Чеклист — ответить ДА или СТОП на каждый пункт

| # | Вопрос | Ответ |
|---|--------|-------|
| 1 | У этого шага **одна** конкретная цель? | ДА / СТОП |
| 2 | Пользователь явно разрешил это действие? | ДА / СТОП |
| 3 | Я работаю только с указанными файлами? | ДА / СТОП |
| 4 | Ни один CONFIRMED объект не будет изменён? | ДА / СТОП |
| 5 | Тест для этого шага определён заранее? | ДА / СТОП |
| 6 | После ответа — стоп и ожидание подтверждения? | ДА / СТОП |

Если хотя бы один ответ — **СТОП** → остановиться, сообщить пользователю причину, ждать инструкции.

---

## Абсолютные запреты (FATAL при нарушении)

- Изменять CONFIRMED код, имена, структуры
- Добавлять зависимости без явного разрешения
- Менять конфигурации (docker-compose, .env, nginx) без явного разрешения
- Продолжать работу без подтверждения пользователя
- Переименовывать, рефакторить, «улучшать» без Change Request

---

## Обязательный заголовок каждого ответа агента

Каждый ответ агента начинается с блока:

```
## Проверка шага
- **Цель:** [одна фраза — что именно делаем]
- **Файлы:** [перечень файлов, которые будут изменены]
- **Тест:** [как именно проверим результат]
- **Чеклист:** ✅ все 6 пунктов ДА
```

---

## Команда /check

Когда пользователь пишет `/check` — агент обязан:
1. Открыть этот файл через `view_file`
2. Явно ответить на каждый из 6 пунктов чеклиста применительно к последнему выполненному шагу
3. Указать все выявленные нарушения GEMINI.md
4. Предложить способ устранения нарушений
